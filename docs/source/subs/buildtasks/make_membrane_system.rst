make_membrane_system 
--------------------

As an *alternative* to a ``solvate`` task, you can use a ``make_membrane_system`` task to build a lipid bilayer and *optionally* embed the protein into it.

Pestifer generates the initial lipid coordinates with a grid packer: it places lipids on a per-leaflet 2-D **orthohexagonal** lattice (oriented, head groups out) and relies on the downstream relaxation MD to resolve the initial overlaps.  It builds the full-size membrane in one shot -- sized to the embedded protein's xy footprint plus the ``embed.xydist`` margin -- so there is no separate patch-packing or replication step.  The water chambers on either side of the bilayer are *not* gridded; they are filled afterward at true liquid density (see `Solvent chambers`_).  The `Task Flow`_ section below describes the process.

.. note::

   **Why an orthohexagonal lattice?**  Rows are offset by half a column pitch, with the row pitch at :math:`\sqrt{3}/2` of the column pitch, so every lipid has six equidistant neighbors at one uniform spacing -- about 7.5% more nearest-neighbor clearance than a square lattice at the same area per lipid.  The square lattice's tight diagonal contacts caused VMD to perceive spurious inter-lipid bonds on the topology-free grid PDB, which in turn made psfgen merge lipids and strand atoms at the origin.  A consequence is that the box dimensions follow from the integer :math:`n_x \times n_y` cell grid (with :math:`n_y` even, so the row offset tiles the periodic box), so **the box is not exactly square**; the grid search scores candidate lattices on lattice vacancies *and* on how close the resulting box aspect ratio is to the target, so it comes out near-square in practice.

``Pestifer`` comes prepackaged with a set of lipid PDB files you can use to build a bilayer.  You can see the full list of available lipids with this command:

.. code-block:: console

  $ pestifer show-resources pdb-repo

``Pestifer`` provides 10 distinct conformers for each lipid molecule, labelled "0" to "9".  These are generated by an athermal Monte Carlo sampler that melts the acyl chains under confinement, so they are fluid-like rather than extended rods -- which matters, because a leaflet gridded from extended rods packs like a gel phase and resists relaxing to a realistic area per lipid.  By default **no conformer is pinned**: the packer draws a conformer per lipid across the whole ensemble, so a leaflet is structurally heterogeneous from the start.  Pin a single conformer for a species only if you have a specific reason to (see ``conf`` and ``lipid_conformers`` below).

If you request a lipid (or other membrane component) that is **defined in the CHARMM force field but not in the shipped PDB repository**, pestifer **generates its conformers on demand** and caches them per-user, so the composition just works.  The first build is a one-time cost (conformer sampling + minimization, loudly logged) and the conformers are cached under ``~/.pestifer/pdbrepository/<release>/lipid/<RESI>/``; subsequent builds reuse them instantly.  A leaflet that declares a phase (``upper_leaflet_phase``/``lower_leaflet_phase``, described below) generates with the Monte Carlo sampler, matching the shipped ensembles; a leaflet specified the legacy memgen way, with no phase, falls back to the older vacuum-MD sampler.  This is the same release-keyed generation cache used for on-demand solvent boxes (see :ref:`the solvate task <subs_buildtasks_solvate>`); disable it with ``charmmff.generate_missing_coordinates: false``, in which case a missing lipid hard-errors and you must build its conformers yourself with ``make-pdb-collection``.

All ``make_membrane_system`` options are documented in the Config Reference pages for :ref:`config_ref tasks make_membrane_system`.

Subtasks
========

There are two main subtask directives in a ``make_membrane_system`` task: ``bilayer`` and ``embed``.  The ``bilayer`` subtask requires specification of the composition (and optionally the size) of the bilayer, while the (optional) ``embed`` subtask requires specification of how the protein should be embedded in the bilayer.

bilayer
+++++++

Bilayer composition is specified either using a single ``composition`` directive or by setting ``packmol-memgen``-style string values to the ``lipids`` and ``mole_fractions`` keys.
   
   - **Composition-specification options**

     - ``composition``: Expects a dictionary with two keys: ``lower_leaflet`` and ``upper_leaflet``.  Each of these keys should map to a list of dictionaries, where each dictionary specifies a lipid name and its fraction in the leaflet.  For example, to specify a symmetric bilayer with 50% POPE and 50% POPC in each leaflet, you would use:

       .. code-block:: yaml

         composition:
           lower_leaflet:
             - name: POPE
               frac: 0.5
             - name: POPC
               frac: 0.5
           upper_leaflet:
             - name: POPE
               frac: 0.5
             - name: POPC
               frac: 0.5

       Naturally, you can specify different compositions for the upper and lower leaflets to create an asymmetric bilayer.  The fractions in each leaflet must sum to 1.0.

       An optional ``conf`` key **pins** a species to a single conformer index.  For instance, to use conformer "3" for half the POPC and conformer "5" for the other half:

       .. code-block:: yaml

         composition:
           lower_leaflet:
             - name: POPC
               frac: 0.5
               conf: 3
             - name: POPC
               frac: 0.5
               conf: 5
           upper_leaflet:
             - name: POPC
               frac: 0.5
               conf: 3
             - name: POPC
               frac: 0.5
               conf: 5

       Note that pinning is rarely what you want: with ``conf`` omitted (the default) the packer already draws a conformer per lipid across the *entire* ensemble, which gives a more heterogeneous starting structure than any hand-picked pair.  Pin a conformer when you need a reproducible or deliberately uniform placement.

     - **Leaflet phase**: each leaflet may declare the physical phase it should be packed in, with ``upper_leaflet_phase`` and ``lower_leaflet_phase``.  The value is either ``Ld`` (fluid, liquid-disordered -- the default, and the historical behavior) or ``Lo`` (liquid-ordered, as in a cholesterol-rich raft):

       .. code-block:: yaml

         composition:
           upper_leaflet_phase: Lo
           lower_leaflet_phase: Ld
           upper_leaflet:
             - name: PSM
               frac: 0.36
             - name: POPC
               frac: 0.17
             - name: CHL1
               frac: 0.47
           lower_leaflet:
             - ...

       The phase selects which **conformer ensemble** the grid packer draws from for that leaflet: ``Ld`` draws the fluid ensemble, ``Lo`` draws an ordered ensemble generated by tuning the Monte Carlo sampler's torsional trans-bias up to a higher chain-order parameter.  Ordered ensembles for the lipids that can form them ship with pestifer, stored under phase-qualified keys (``PSM`` → ``PSM__Lo``); ensembles for others are generated on demand like any missing conformer.

       .. note::

          **Why the phase is an input and not an outcome.**  A cholesterol-rich saturated leaflet really does undergo a liquid-ordered transition, but that is a *phase change*, not equilibration -- MD cannot cross Ld ↔ Lo on build timescales, so a leaflet packed from fluid conformers will simply fail to converge, drifting slowly toward an order it never reaches.  Declaring the phase up front packs it in the right state to begin with.  Note also that whether a given lipid can actually reach Lo is decided by its *measured* chain order, not by inspecting its structure, so a sphingomyelin's trans double bond does not misclassify it; lipids that cannot order reuse the fluid ensemble.

     - ``lipids`` and ``mole_fractions``: These strings specify the lipid composition in the bilayer.  Each is a ``packmol-memgen``-style string, where each lipid (or mole fraction) is separated by a comma.  For example, to specify a symmetric bilayer with POPE and POPC, you would use:

       .. code-block:: yaml

         lipids: POPE:POPC
         mole_fractions: 0.5:0.5

       This notation specifies that *both* leaflets have the *same* composition.  For an asymmetric bilayer, the packmole-memgen string format is a bit more complex -- you have to use ``//`` to delineate the two leaflets.  You can specify the upper and lower leaflets separately, like this:

       .. code-block:: yaml

         lipids: POPE:POPC//POPE:POPC
         mole_fractions: 0.5:0.5//0.6:0.4 
       
       You can also use a single packmol-memgen-style string to specify the conformers used for each lipid.  For example, to specify that the bilayer uses conformer "3" and the lower leaflet uses conformer "5" for POPC, you would use:

       .. code-block:: yaml

         lipids: POPC:POPC
         mole_fractions: 0.5:0.5
         lipid_conformers: 3:5

   - **Optional subdirectives**: The ``bilayer`` subdirective can also include optional subdirectives to control how the bilayer is built and relaxed:
     
     - ``SAPL`` specifies the target surface area per lipid (SAPL) for the bilayer, applied to both leaflets.  It sets the initial lattice spacing.  This is only an *initial* value; the equilibrium area is found during the ``relaxation_protocols`` relaxation.  If you do not specify a ``SAPL``, pestifer will use a default value of 75.0 :math:`Å^2` per lipid.
   
     - ``relaxation_protocols`` specifies protocols to relax the bilayer before embedding.  Each protocol is a list of stages; a stage is a dictionary with a single key naming its type.  Two types are supported: ``md``, a fixed-length stage that runs exactly as written, and ``membrane_equilibrate``, a **self-terminating** stage that runs in chunks until its density and area convergence criteria are met.  The ``patch`` protocol relaxes the two per-leaflet *calibration* patches (asymmetric builds only), and the ``quilt`` protocol relaxes the full-size, directly-gridded membrane.  Long ``NPT``/``NPgT`` ``md`` stages are automatically split into a ramp of restarts so the condensing cell never outgrows NAMD's startup patch grid.  Options are documented in the Config Reference pages for :ref:`config_ref tasks md` and :ref:`config_ref tasks membrane_equilibrate`.

       A protocol typically ends with a ``membrane_equilibrate`` stage: some short ``md`` stages to melt the lattice out, then a self-terminating stage that decides for itself when the membrane has settled.  This matters most on the calibration path, where the *whole point* is to measure a converged area per lipid -- a fixed-length NPgT tail either wastes time or, worse, stops short and reports an area the membrane had not actually reached.

       .. code-block:: yaml

         relaxation_protocols:
           patch:
             - md:
                 ensemble: minimize
                 nsteps: 1000
             - md:
                 ensemble: NVT
                 nsteps: 1000
             - membrane_equilibrate:
                 constant_ratio: false   # let a calibration patch relax x and y independently

       .. note::

          ``constant_ratio`` (default ``true``) locks the cell's :math:`L_x{:}L_y` ratio during the tensionless area stage.  That is right for an *embedded* membrane, whose lateral aspect must stay stable.  It is wrong for a **calibration patch**: on a non-square orthohexagonal box, a locked skewed ratio drives the relaxation to over-condense the area along the short axis instead of settling, and the patch never converges.  Set ``constant_ratio: false`` on calibration protocols so the fully flexible cell can find its own shape.

     - ``solvents`` and ``solvent_mole_fractions`` are optional packmol-memgen-style strings that specify the solvent composition.  Pestifer uses 100% TIP3P water by default.
     - ``solvent_to_lipid_ratio`` specifies the number of waters to include in the extra-membrane region of the box as proportional to the number of lipids.  If you do not specify this, pestifer will use a default of 32 TIP3P water molecules per lipid.
     - ``patch_nlipids`` specifies the number of lipids in each calibration-patch leaflet (asymmetric builds only).  It expects a dictionary with keys ``upper`` and ``lower``, each an integer.  If you do not specify this, pestifer will use a default of 100 lipids per leaflet.
     - ``quilt_grid_slack`` (default 1.05) is the linear factor by which a protein-embedding quilt is gridded *looser* than its calibrated stress-free box area, giving the lipid placement a little clearance before the tensionless relaxation condenses it back to the preferred per-leaflet APL.  1.0 grids exactly at the stress-free area; the 1.05 default is about 5% extra area, a token placement margin.  (The former 1.15 -- some 32% extra area -- was needed only for the square lattice's tight contacts, and left the quilt badly under-dense.)

Solvent chambers
++++++++++++++++

The grid packer places **lipids only**.  The extra-membrane water chambers on either side of the bilayer are filled afterward, by a VMD ``solvate``/``autoionize`` step that runs after the lipid ``psfgen``: it tiles a pre-equilibrated water box into exactly the lipid system's cell (no padding) and drops the water that clashes with the dense lipid slab, leaving water only in the chambers, at true liquid density.

This replaced an earlier cubic water lattice, whose voids the barostat would close early in the relaxation -- distorting the bilayer while the water caught up to liquid density.  Starting near density equilibrium, post-embed equilibration converges markedly faster (example 16's post-embed stage went from roughly 3 hours to about 1 hour 49 minutes).

``embed``
+++++++++

This subtask requires a set of specifications for embedding the protein in the bilayer.  
   
   - ``xydist`` and ``zdist`` are the lateral and membrane-nomral margins of the simulation box; these values are added to corresponding coordinates extremal atoms to make sure the box is big enough.
   - ``z_head_group`` and ``z_tail_group`` are VMD ``atomselect`` strings that define the center of mass z-coordinate for the membrane-proximal regions of the protein.  The protein is rotated so that the axis from the ``z_tail_group`` center to the ``z_head_group`` center aligns with the membrane normal (:math:`+z`).
   - ``orient`` is a general vector-based orientation, equivalent to the ``ALIGN`` operation of the :ref:`transrot <subs_buildtasks_psfgen_mods_transrot>` mod: it rotates the protein so that a ``source`` vector is carried onto a ``target`` vector by the minimal (roll-free) rotation about the protein's center of mass.  Each of ``source``/``target`` is either a literal 3-vector ``[x, y, z]`` or a pair of atomselections ``[selA, selB]`` whose mass-weighted centers define the vector (from ``selA`` to ``selB``).  ``orient`` takes precedence over ``z_head_group``/``z_tail_group`` when both are given; the shorthand above is exactly ``orient: {source: [<z_tail_group>, <z_head_group>], target: [0, 0, 1]}``.  Use ``orient`` when you want to target something other than :math:`+z` (e.g. a tilted normal) or specify the source as a literal vector.
   - ``z_ref_group`` specifies via VMD atomselection whose center of mass sits at the the middle of the bilayer at a particular ``z_value``.
   - ``no_orient`` is a boolean that specifies whether the protein should be oriented to the membrane normal.  If ``True``, the protein will be oriented so that its z-axis is aligned with the membrane normal.  If ``False``, the protein will not be oriented, and the orientation it has in its own structure file will be preserved.  It is ``False`` by default.  When ``False``, an ``orient`` spec (or the ``z_head_group``/``z_tail_group`` shorthand) is used to determine the orientation of the protein in the bilayer.


Example
========

An example ``make_membrane_system`` task is specified below:

.. code-block:: yaml

  - make_membrane_system:
      bilayer:
        packer: grid
        SAPL: 50.0           # only the initial guess; the grid is sized from the *measured* APL
        salt_con: 0.154
        cation: POT
        anion: CLA
        composition:
          upper_leaflet_phase: Lo   # saturated, cholesterol-rich raft leaflet
          lower_leaflet_phase: Ld   # unsaturated leaflet stays fluid
          lower_leaflet:
            - name: POPE
              frac: 0.09
            - name: SOPS
              frac: 0.18
            - name: SOPE
              frac: 0.30
            - name: CHL1
              frac: 0.43
          upper_leaflet:
            - name: PSM
              frac: 0.36
            - name: POPC
              frac: 0.17
            - name: CHL1
              frac: 0.47
        seed: 270272
        relaxation_protocols:
          patch:
            - md:
                ensemble: minimize
            # brief hot NVT melts the lipids off the initial lattice, then settle at temperature
            - md:
                ensemble: NVT
                nsteps: 2000
                temperature: 410
            - md:
                ensemble: NVT
                nsteps: 2000
                temperature: 310
            - membrane_equilibrate:
                temperature: 310
                pressure: 1.0
                area_plateau_tol: 0.005
                max_steps: 800000
                constant_ratio: false
          quilt:
            - md:
                ensemble: minimize
            - md:
                ensemble: NVT
                nsteps: 1000
                temperature: 310
            - membrane_equilibrate:
                temperature: 310
                max_steps: 800000
      embed:
        xydist: 40
        zdist: 10
        z_head_group: "protein and resid 667"
        z_tail_group: "protein and resid 710"
        z_ref_group:
          text: "protein and resid 696"
          z_value: 0.0

This is (lightly trimmed) the membrane build from :ref:`example mper-tm viral bilayer`.  A few things worth noting: the two protocols are *lists* of stages; the calibration patch relaxes with ``constant_ratio: false`` and a plateau-gated area tolerance, because its converged APL is what sizes the whole grid; and the cholesterol-rich upper leaflet is declared ``Lo`` so it is packed already ordered rather than trying (and failing) to order during relaxation.

If you are including cholesterol or any other sterols in your bilayer, a ``make_membrane_system`` build now guards against pierced sterol rings automatically: during the membrane's relaxation, just before the first dynamics stage, it inserts a lipid ``ring_check`` (which deletes the offending lipid) followed by a short minimize, so a lipid tail threaded through a sterol ring is removed before it can destabilize the run.  It is still recommended to follow the ``make_membrane_system`` task with an energy minimization and an explicit ``ring_check`` to catch glycan or protein rings (which the automatic guard, checking only lipids, does not) when the embedded protein is glycosylated.  This is illustrated in :ref:`example mper-tm viral bilayer`.

Task Flow
=========

.. note::

   "Quilt" is a legacy label for the *full-size* membrane and its relaxation -- it
   dates from an earlier packer that tiled small patches into a quilt.  The grid
   packer does no tiling, so a build's ``*-quilt`` artifacts (``grid-quilt``,
   ``psfgen-quilt``, ``equilibration-quilt``) are the whole membrane, **not**
   patches.  Patches appear only in *asymmetric* builds, as the per-leaflet
   calibration patches described below.

For a **symmetric** bilayer, pestifer builds the full-size membrane directly: it grids both leaflets at the requested composition and initial ``SAPL``, sizing the box to the embedded protein's xy footprint plus the ``embed.xydist`` margin (or to ``patch_nlipids`` otherwise).  The gridded membrane is relaxed with the ``quilt`` protocol, and the protein is then embedded.  There is no separate patch or replication step.

For an **asymmetric** bilayer (different leaflet compositions), pestifer first relaxes two symmetric *calibration* patches -- one per leaflet composition -- with the ``patch`` protocol, to measure each leaflet's preferred area per lipid (APL).  It then grids the full membrane (sized to the protein footprint when embedding) at per-leaflet counts in the stress-free ratio :math:`n_\text{upper}/n_\text{lower} = \text{APL}_\text{lower}/\text{APL}_\text{upper}`, so the two leaflets carry equal area at zero differential stress *by construction* -- no leaflet extraction or excess-lipid deletion is required.  The full membrane is then relaxed with the ``quilt`` protocol before embedding.

In either case, the gridded lipids are built into a PSF and the water chambers are then filled by the ``solvate`` step described above, so the membrane enters its relaxation protocol already at liquid density.

When the calibration relaxation is gated by a ``membrane_equilibrate`` stage that reports convergence, pestifer **trusts** the APL it measured and grids from it directly.  Because an overestimated APL would condense the quilt tighter than the protein it has to accommodate, the build also remembers the protein's bare xy footprint and verifies at embedding time that the equilibrated (condensed) box still spans it, rather than discovering the mismatch as a failed embed.

Other Notes
===========

Pestifer's ``make_membrane_system`` task is inspired by the `packmol-memgen package <https://ambermd.org/tutorials/advanced/tutorial38/index.php>`_.  For instance, we borrow ``packmol-memgen`` syntax for specifying composition (optionally; the preferred syntax is to use a ``composition`` dictionary in the yaml input).  However, we do not use any precomputed surface-areas per lipid.  Instead, we allow the user to specify a single value for SAPL and then use an MD-based relaxation protocol to achieve a laterally equilibrated bilayer system prior to any embedding.  Packmol-memgen allows for generation of asymmetric bilayers but does not provide a way to guarantee lack of spontaneous curvature that might result, beyond assuming its pre-computed SAPL's are correct.

Most of the wall-clock time for a membrane build is relaxation MD, which can run from a few minutes to several hours depending on the system size and the number of steps in each protocol.  The *coordinate generation* itself is cheap: the grid packer places lipids deterministically in seconds.  See :ref:`example mper-tm viral bilayer` for an example of a protein-embedded, heterogeneous asymmetric bilayer system.
