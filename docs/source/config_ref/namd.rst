``namd``
========

These are specifications for NAMD3, including default input configuration parameters for various classes of simulations.

Single-valued attributes:

  * ``namd-version``: version of NAMD to run (2 or 3) (default: 3)

  * ``processor-type``: Explicit control over whether NAMD runs on CPU or GPU. 'auto' (the default) elects GPU only when paths.namd3gpu names a separate binary that resolves on PATH, and otherwise runs CPU (the historical auto-detect behavior); 'gpu' forces GPU mode even when a single binary serves both CPU and GPU builds (paths.namd3gpu == paths.namd3), which 'auto' can never elect; 'cpu' forces CPU and ignores any GPU binary. The 'run --gpu' CLI flag is equivalent to setting this to 'gpu'. (default: auto)

    Allowed values: ``auto``, ``cpu``, ``gpu``

  * ``ncpus``: number of processing elements (PEs) for NAMD; 0 means auto-detect from SLURM environment or local CPU count (default: 0)

  * ``seed``: Base RNG seed for NAMD. NAMD's own default is drawn from the clock, so a run's stochastic inputs -- initial velocity assignment and the Langevin thermostat/barostat streams -- were different every time and could not be re-derived; pestifer therefore pins them. Each NAMD invocation in a build derives its own stream from this base deterministically. Note what this does and does not buy: it makes the stochastic inputs of a build reproducible, NOT its trajectory. A parallel NAMD run is not bitwise reproducible, because force contributions are summed in an order that depends on message arrival and on load-balancer decisions, and floating-point addition is not associative; in chaotic dynamics those last-bit differences grow. Set 0 to restore NAMD's clock-derived behavior. To generate replicas of one system, run the same config with different values here (or with 'run --seed'); the seed is what makes a replica labeled and re-derivable rather than anonymous. (default: 27021972)

  * ``cpu-parallel-launcher``: How CPU-mode NAMD is launched when running under SLURM. 'auto' (the default) uses 'numactl' for a single-node allocation and 'srun' when SLURM_NNODES > 1, since a single-node multicore launch cannot span nodes. 'numactl' runs a single-node multicore/SMP NAMD build via 'numactl --interleave=all namd3 +p N'. 'srun' launches an MPI NAMD build across every allocated SLURM task (nodes x ntasks-per-node), which is required to span multiple nodes. 'mpirun' launches an MPI NAMD build via the MPI runtime's own process manager ('mpirun -np N namd3'); use this when plain srun leaves ranks as independent 1-PE jobs (common with Intel MPI). 'charmrun' launches a net (charmrun) NAMD build across nodes via charmrun's MPI launcher. (default: auto)

    Allowed values: ``auto``, ``numactl``, ``srun``, ``mpirun``, ``charmrun``

  * ``srun-mpi-type``: PMI plugin passed to srun as '--mpi=<type>' (e.g. pmi2 or pmix) when cpu-parallel-launcher resolves to 'srun'. Empty (the default) emits a bare 'srun'. Set this if srun launches every rank as an independent 1-PE MPI job; the valid values come from 'srun --mpi=list' on your cluster. (default: )
