.. _config_ref tasks ring_check segtypes:

``segtypes``
------------

  * lipid
  * glycan
  * protein


A list you supply **replaces** these defaults entirely.

list of segment types whose rings are checked for piercing.  The action depends on the pierced ring's segtype: a LIPID ring is cleared by rotation and, failing that, by `delete`; a GLYCAN ring is fatal (a glycan cannot be deleted without breaking the glycan tree); a PROTEIN side-chain ring (His/Phe/Tyr/Trp/Pro) is cleared by rotating the side chain, and is fatal if no rotation clears it.  The default checks ALL THREE.  It used to have none, so a bare `ring_check:` silently checked nothing -- and every shipped example asked for [lipid, glycan] only.  Example 17 was measured on 2026-10-16 to carry 2-6 protein-lipid ring piercings at the post-embed hand-off of every replica, CHL1 rings threaded by MPER side chains and PHE rings threaded by acyl tails, none of which anything in the pipeline could see.  An empty list is a configuration error and stops the build. . `list_defaults: replace` is load-bearing.  ycleptic APPENDS a list default to what the user wrote by default, so without it `segtypes: [lipid]` would resolve to `[lipid, glycan, protein, lipid]` -- silently checking three segtypes for someone who asked for one.  With it, an omitted key gets all three and an explicit list is taken as written.
