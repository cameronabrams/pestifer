``ring_check``
==============

Parameters controlling pierced-ring checks and how detected piercings are resolved. The action taken depends on the pierced ring's segtype (see segtypes)

Single-valued attributes:

  * ``delete``: for a pierced LIPID ring that NO rotation could clear, which segment(s) to delete: 'piercee' (the ring's segment), 'piercer' (the threading bond's segment), 'both' (piercee plus the piercer when it too is a lipid), or 'none' (no deletion; the piercing is reported and the build STOPS).  Does not apply to glycan or protein piercings, which are always fatal when unresolved.  The default is 'none' because a threaded ring is a topologically wrong molecule -- no further dynamics can unthread it -- so a build carrying one has already failed whether or not NAMD complains, and deleting a lipid to hide it silently changes the composition being built.  Set this to 'piercee' only when losing a lipid is preferable to losing the build. (default: none)

    Allowed values: ``piercee``, ``piercer``, ``both``, ``none``

  * ``cutoff``: candidate search radius (Å) between a bond midpoint and a ring COM; only candidates within this distance are tested for piercing. Any value >= the piercing gate (3.5 Å, in PSFRing.pierced_by) gives identical results, so the default is kept just above it to prune candidates and keep the whole-system scan fast on large membranes (default: 4.0)

  * ``max_ring_size``: only rings of at most this many atoms are considered (keeps real 5/6-membered rings while skipping the giant chordless cycles a disulfide makes through the protein backbone) (default: 7)
