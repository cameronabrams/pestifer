``ring_check``
==============

Parameters controlling pierced-ring checks and how detected piercings are resolved. The action taken depends on the pierced ring's segtype (see segtypes)

Single-valued attributes:

  * ``delete``: for a pierced LIPID ring that NO rotation could clear, which segment(s) to delete: 'piercee' (the ring's segment), 'piercer' (the threading bond's segment), 'both' (piercee plus the piercer when it too is a lipid), or 'none' (no deletion; the piercing is reported and the build STOPS).  Does not apply to glycan or protein piercings, which are always fatal when unresolved.  The default is 'none' because a threaded ring is a topologically wrong molecule -- no further dynamics can unthread it -- so a build carrying one has already failed whether or not NAMD complains, and deleting a lipid to hide it silently changes the composition being built.  Set this to 'piercee' only when losing a lipid is preferable to losing the build. (default: none)

    Allowed values: ``piercee``, ``piercer``, ``both``, ``none``

  * ``on_unresolved``: what to do when a resolving pass is left with a lipid-ring piercing no move clears: 'stop' (the default) ends the build, naming every remaining piercing; 'continue' logs them and hands them to the next stage.  Meant only for a check that runs before the FIRST minimization of a freshly placed structure -- make_membrane_system sets it there itself -- because that minimization untangles most of what placement threads (on example 17's calibration patch, 20 threadings went in and 3 came out).  Requires resolve: true and delete: none, and never applies to protein or glycan rings, which stay fatal.  The checks after the minimization still resolve and still stop the build, so nothing threaded reaches dynamics. (default: stop)

    Allowed values: ``stop``, ``continue``

  * ``resolve``: whether this pass may MOVE anything.  True (the default) resolves what it finds, by rotation and then by `delete`.  False detects and reports only: any piercing found is fatal.  A verify-only pass is the terminator of the rotate-then-minimize loop that a gridded membrane's relaxation splices around each minimization -- a rotation is a rigid displacement that leaves new heavy-atom clashes behind, so one that is not followed by a minimize hands dynamics coordinates nothing has relaxed, which is how example 17 reached a RATTLE failure on 2026-10-19 with all six failing atoms in or beside a branch the last check had rotated.  By the verify pass the loop has already rotated and relaxed twice, so anything left is something that loop cannot fix (a doubly-threaded molecule, or a leaflet built far from its true SAPL) and is worth stopping for. (default: True)

  * ``cutoff``: candidate search radius (Å) between a bond midpoint and a ring COM; only candidates within this distance are tested for piercing. Any value >= the piercing gate (3.5 Å, in PSFRing.pierced_by) gives identical results, so the default is kept just above it to prune candidates and keep the whole-system scan fast on large membranes (default: 4.0)

  * ``max_ring_size``: only rings of at most this many atoms are considered (keeps real 5/6-membered rings while skipping the giant chordless cycles a disulfide makes through the protein backbone) (default: 7)
